# P05 Hybrid RAG (Context Store + BM25/FAISS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved P05 Drive-backed, per-project Context Store with locally materialized BM25 + FAISS retrieval, incremental updates, generation rollback, and evidence-backed Context Gateway recall, without introducing a new authority.

**Architecture:** Keep Agent Platform stateless: its existing `createContextGateway` and `createContextStore` validate requests and delegate to a versioned Execution Plane client. Implement real corpus materialization, local embeddings, FAISS, hybrid retrieval and generation publication in `menezesx2k26-byte/resident-node`, reusing the P04 Rust interfaces and P05 manifest/generation policy from PR #32. Google Drive stores immutable normalized corpus and snapshots; the primary Execution Plane exclusively coordinates generation publication, with recoverable current/previous receipts. Never run SQLite/FAISS files directly in Drive-sync directories.

**Tech Stack:** Node.js `>=22 <25` (CommonJS/`node:test`), Rust `>=1.89`, `rusqlite` FTS5, native FAISS, pinned local ONNX embedding model, Google Drive storage through approved authenticated transport, GitHub Actions across supported host OSes.

**Spec:** `docs/architecture/spec-kit/00-constitution.md`, `02-target-architecture.md`, `03-authority-matrix.md`, `07-migration-phases.md` (P05), `08-architecture-gates.md`, `09-rollout-rollback.md`, `10-acceptance-criteria.md`, plus `docs/superpowers/specs/2026-10-02-platform-consolidation-design.md`.

**Repositories:**

- Execution Plane source: `menezesx2k26-byte/resident-node` (future name only).

## Global Constraints

- **Entry gate:** P05 formal entry is blocked until required P03/P04 gates are evidenced. Source-only, offline preparatory implementation may be reviewed separately; no live cutover or P05 exit assertion before P04 indexing runtime and single-primary/rollback evidence are valid.
- Exactly one authoritative writer exists per durable domain. Git owns source/project documents; private Memory owns personal context; Engram owns episodic memories; PersistFlow owns run state; Context Store owns retrieval corpus projection; indexes are expendable derivatives.
- Normal project recall accepts only deterministic `project/<owner>/<repo>` derived from trusted repository/workspace identity. Cross-project retrieval requires an explicit allowlist; model output cannot select a scope.
- Initial retrieval must use BM25 + FAISS with pinned local embeddings, physically separated per-project indexes, structural chunks with source/ref/path/revision provenance, and no serving dependency on RAGFlow or Hindsight.
- Drive stores durable corpus/manifests/index snapshots; active SQLite/FAISS/index builds run from a verified local non-synced directory.
- Publication keeps `current` and `previous`, verifies both observed generations and the idempotency key, and permits exact rollback; never delete `previous` before replacement validation.
- Agent Platform has no direct SQLite, filesystem authority, credential custody, or provider/framework types in public contracts.
- Do not ingest private chats, secrets, account Memory or unrestricted Drive into the pilot; begin with the pre-scanned public `edu-trigonometria-pretemporada` Git/docs corpus. Do not add paid compute/model API, new control planes or new permanent databases.
- No Spec Kit mutation, RAGFlow serving, repo archival, production cutover, or migration-phase skip.
- Tests are RED before implementation, GREEN after minimal change, then architecture/spec-kit regression check and small commit. Update evidence with exact commit/command and mark unknowns honestly.
- Profiles must identify the real embedding model/version and SHA-256 artifact digest; a model must be locally installed through an approved reproducible channel before a runtime may serve it. No implicit online model download while serving.
- Preserve preexisting production runtime paths until measured caller migration and rollback gates; no action is authorized on external accounts or billed systems solely by this plan.

## Review Focus

1. **Replay with identical idempotency key but changed candidate:** must reject conflicting replay, retain both generation pointers, and avoid a second publication (Task 4 test `same_key_changed_payload_rejected`).
2. **A corpus manifest is valid JSON but points outside its project or to a path traversal:** must reject before reading any data (Task 2 test `rejects_foreign_or_traversal_corpus_before_read`).
3. **Crash after uploading immutable index files but before current-pointer CAS:** recovery must leave old current serving and safely replay/garbage-collect unreferenced derived data (Task 4 test `crash_before_cas_preserves_current`).
4. **FAISS dimension/profile mismatches the BM25 artifact or embedding model:** candidate must never become current, and the prior good generation must remain queryable (Task 6 test `rejects_mixed_profile_or_dimension`).
5. **Retrieval returns an older contradictory source alongside current Git evidence:** citation/provenance and revision ordering must prefer the current source, or explicitly fail closed rather than misrepresent stale text as current (Task 9 test `prefers_current_revision_with_contradictions`).
